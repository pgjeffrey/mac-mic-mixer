按需采集实测使用用户当前三路配置。接收进程读取虚拟输入后，约 0.61 秒内观察到输出端、DJI 与内置麦克风处于运行状态，最后一个接收进程结束后约 1.29 秒观察到这些端点空闲。该测量包含接收端启动和轮询开销。两次六秒接收与一次四秒接收分别取得 288000、288000、192000 帧，样本只在进程内存中处理。MiRemoteV 的全局运行标记在空闲时仍为 1，其已有外部客户端与本 App 的按需状态分别记录。日志位于 `.build/logs/demand-runtime.log` 和 `.build/logs/demand-runtime.json`。

## Mac 构建

1. 确认构建机使用完整 Xcode 26.5 或更新版本，安装 CMake 3.28+、Python 3 和 Git。
2. 执行 `make sources`、`make test`。
3. 执行 `make package ARCH=arm64`，保存完整编译日志和错误。
4. 核对 `dist/arm64` 中应用、驱动、安装包与卸载包；检查签名和应用包内动态库。
5. CI 工作流只是可执行配置，未在本次会话提交或触发远程构建。

## 安装和虚拟链路

1. 退出已有实例后运行 Install 安装包，按系统提示授权并重启。
2. 打开应用；确认虚拟设备就绪，系统和目标 App 的输入列表出现 `Mac Mic Mixer`。
3. 添加可用输入，开始混音并授予麦克风权限。
4. 避开通话时段，从“连接诊断”执行测试音回读，保存实际结果。失败结果在恢复混音后仍应可见。
5. 打开目标 App，选择 `Mac Mic Mixer`。分别讲话、同时讲话、分别静音，确认实际录音或对端收到的音频。仅读取左声道或单声道时两路也必须可闻。

## 恢复及持续运行

- 每一路分别断开、重连；检查另一输入仍可用，缺失设备不被默认输入替换。
- 调整设备采样率和切换蓝牙工作状态，检查是否能恢复有效音频。
- 休眠、唤醒后检查实际目标 App 收音。
- 连续运行至少 60 分钟，记录积压丢帧、欠载变化、资源占用、听感及延迟增长。
- 关闭窗口后继续收音；退出后停止；再次打开可正常启动。
- 登录启动时让已配置蓝牙设备延迟连接，确认设备到达后可开始混音。
- 拒绝、撤销及重新授予权限，检查状态与恢复动作。
- 升级、卸载和重新安装后重启，检查虚拟设备与其他音频设备均符合预期。

填写实测时至少记录 Mac 型号、系统版本、设备 UID/名称、目标 App 版本、步骤、结果和失败恢复情况。用户设备名称不需在实现中预先写死。
