# Mac Mic Mixer 实施方案

## 1. 项目目标

开发一个独立的 macOS 多麦克风混音软件，将多个不同品牌的音频输入合并，作为一个虚拟麦克风提供给会议、录音、语音输入等应用。

用户已确认使用 Apple 芯片 Mac。输入不限定品牌、名称及连接方式，凡 macOS 输入列表中可用的设备均可选择；最初的目标设备为大疆麦克风和另一台蓝牙输入。项目使用 Mac 自带蓝牙连接，不增加硬件接收器。具体 macOS 版本尚未提供，首版运行部署基线为 macOS 13。

基本链路：

```text
大疆麦克风 ───┐
              ├─→ 专用软件采集与混音 ─→ 虚拟麦克风 ─→ 目标应用
另一台输入 ───┘
```

前提是 macOS 能同时向软件提供两台设备的有效音频输入。设备已经配对、显示为已连接，或分别能够收音，均不足以证明双路同时采集已经可用。

## 2. 技术路线

首版采用“OBS 音频后端复用 + BlackHole 虚拟音频驱动 + 独立管理界面”的方案，优先保留成熟代码的模块边界，固定依赖版本。

| 部分 | 实现方式 | 职责 |
| --- | --- | --- |
| 音频采集及混音 | OBS 的 libobs、macOS 音频采集模块与本项目 HAL 输出适配 | 打开多个输入，处理格式转换、缓冲、音量及混音，输出到虚拟设备 |
| 虚拟麦克风 | 基于 BlackHole 源码构建的 Core Audio HAL 插件 | 将软件写入的混音提供给其他应用作为音频输入 |
| 管理界面 | 独立 macOS 应用，建议 SwiftUI 加音频侧 C/C++ 桥接 | 选择设备、控制音量和静音、展示实际收音与运行状态 |
| 安装与卸载 | 同一安装包交付应用和虚拟音频插件 | 完成插件安装、权限引导、版本检查及卸载 |

OBS 提供可供其他程序调用的后端库 libobs。首版以其公开接口组织集成，先验证依赖构建和无 OBS 原版界面的运行链路。libobs 包含音视频能力，实际构建可能仍需保留初始化或链接所需的其他依赖，具体边界以编译和运行结果为准。

当前实现保留 libobs 的正式混音路径。OBS 33 的音频根节点依赖主画布，因此引擎初始化一个不显示的 16 × 16、每秒 1 帧的 Metal 画布，不提供视频或录制功能。混音经 `audio_output_connect` 进入有界缓冲，再由本项目 HAL 输出适配写入隐藏的虚拟输出设备；该适配便于控制输出状态和缓冲积压。更多实现细节见 [架构说明](docs/architecture.md)。

用户日常只需启动本项目应用。虚拟音频插件由 macOS 音频服务加载，属于独立的安装组件，不能简单等同于主程序中的普通函数。首次安装插件需要系统授权，并可能需要重新加载音频服务或重启，按实际安装机制处理。

## 4. 首版功能范围

- 从系统列表选择多个独立输入，包括蓝牙、USB、内置麦克风和虚拟输入；排除本项目自己的输入，避免反馈回路。
- 分别设置两路音量和静音，显示每路实时电平。
- 将两路混成同一份人声信号，提供总音量和输出电平。
- 对外提供一个名称明确的虚拟麦克风，供目标应用选择。
- 展示设备缺失、权限不足、采集失败、输出失败及正在恢复等实际状态。
- 记住用户选择的设备与音量设置，处理设备重连和系统休眠唤醒。
- 提供安装与卸载流程。

首版仅处理实时音频混音，不扩展直播、视频、音效插件宿主、录音归档及网络音频传输。

## 5. 音频处理约定

### 输入与设备身份

通过 Core Audio 设备标识定位输入，显示设备名称供用户选择。蓝牙配对交由 macOS；本项目读取系统已经暴露的音频设备。

设备断开时保留用户选择，显示对应输入不可用；其他输入是否继续输出应有明确状态反馈。设备重新出现后按原标识尝试恢复，避免静默切换到系统默认麦克风。

### 格式、时钟与混音

内部处理格式暂以 `48 kHz / Float32` 为集成目标，输入端保留设备实际支持的采样率，并在需要时转换。该目标不代表蓝牙麦克风能提供原生 48 kHz 音质。

不同设备具有不同采样率、缓冲和时钟，需验证所复用音频链路的转换、同步和缓冲行为。蓝牙延迟、长期漂移及不同设备之间的时差需要实测，不能仅凭使用成熟项目就认为已经解决。

两路输入按各自增益求和，形成共同的混音。若虚拟设备采用双声道，对左右声道输出同一份合并信号，使只读取一个声道的应用也能听到两支麦克风。避免将两支麦分别只放到左右声道。

提供增益调整及过载提示，验证同时讲话时的峰值与失真；是否增加限幅在集成实测后确定。

### 输出及生命周期

按虚拟设备标识定位输出，反馈驱动缺失、版本不匹配及设备无法打开等问题。成功安装驱动不等于混音已经能够输出。

应用默认按需采集，启用后在后台待命。其他 App 实际读取公开虚拟麦克风时开始采集，最后一个使用者结束后经过约一秒缓冲释放输入。检测依据公开输入端的使用状态，混音器自己的隐藏输出不会触发采集。设置中可关闭按需采集，改为持续混音。最小化窗口后继续运行，明确退出后停止音频处理。退出后仍然安装的虚拟设备行为按验收步骤验证。

主程序启动、停止、重连和输出重建应有统一生命周期，正确释放音频资源，避免重复打开设备。运行诊断默认不记录麦克风正文。

## 6. 界面约定

使用一个简洁的操作窗口，展示以下内容：

- 输入 A、输入 B 的设备选择、连接状态、电平、音量及静音。
- 混音输出的虚拟设备名称、总音量、电平及实际运行状态。
- 开始、停止和必要的权限或驱动安装引导。

“运行正常”至少需要实际输入采集和输出设备均工作。权限未获得、只有设备名称、只创建了虚拟设备或主进程仍存在，都不能单独作为成功依据。

## 7. 实施步骤

1. **整理资料与固定源码基线。** 保存方案、上游代码、版本及模块入口。
2. **验证用户设备。** 在目标 Mac 上核对系统版本、两台设备名称和输入格式，证明两路能同时持续收音。
3. **打通最小音频链路。** 构建 libobs 及必要模块，验证两路采集、混音和写入 BlackHole，使用接收应用检查实际音频。
4. **封装独立应用。** 接入设备选择、音量、静音、电平与生命周期管理，处理权限、断线和休眠恢复。
5. **整理虚拟设备与安装包。** 基于源码构建项目自己的虚拟设备组件，完成命名、版本、签名、安装和卸载验证。
6. **完成稳定性验收。** 执行连续运行、设备恢复和目标软件兼容性测试，再确定交付版本。

## 8. 验证与验收

| 场景 | 验证要求 |
| --- | --- |
| 两路同时采集 | 分别讲话及同时讲话，确认两路均有有效音频 |
| 单路静音和音量 | 控制仅影响所选输入，另一输入仍正常 |
| 单声道兼容 | 目标应用仅读取单声道时仍能收到两路合并声音 |
| 峰值与失真 | 两人同时讲话时检查过载、削波及音量变化 |
| 连续运行 | 首轮至少连续运行 60 分钟，检查丢音、卡顿、延迟增长、漂移及资源变化 |
| 蓝牙断开与重连 | 任一路断开后状态准确，另一输入行为符合约定，原设备重连后可恢复 |
| 休眠和唤醒 | 唤醒后检查两路输入、虚拟输出和目标软件中的实际收音 |
| 退出及再次启动 | 停止处理并释放资源，重新启动后无重复输入和旧音频残留 |
| 权限及驱动异常 | 未授权、插件缺失或输出失败时准确反馈，无虚假正常状态 |
| 目标应用兼容性 | 使用用户实际软件验证，并覆盖录音回放、目标软件重启及输入切换 |
| 安装与卸载 | 验证目标 Mac 上的权限、签名、安装、升级和卸载行为 |

成熟上游组件提供复用基础，本项目整合后的稳定性仍以目标 Mac、两台实际设备和目标软件的验证结果为准。

## 11. 开发与构建

```sh
make help
make sources
make test
```

Mac 构建机需安装完整 Xcode 26.5 或更新版本并通过 `xcode-select` 选中，安装 CMake 3.28 或更新版本，并具备 Python 3.9+。Xcode/SDK 要求来自固定的 OBS 33.0.1 源码，不通过降低声明版本来规避；构建机要求与应用运行部署目标 macOS 13 是不同概念。

在满足要求的 Mac 上：

```sh
make build ARCH=arm64
make package ARCH=arm64
```

构建会按上游固定校验值获取 OBS 依赖，首次构建需要网络和较多磁盘空间。生成结果位于 `dist/arm64/`：

- `Mac Mic Mixer.app`：主程序。
- `MacMicMixer.driver`：虚拟音频插件。
- `MacMicMixer-0.1.0-arm64-Install.pkg`：完整安装包。
- `MacMicMixer-0.1.0-arm64-Uninstall.pkg`：卸载包。

`dist/MacMicMixer-0.1.0-source.tar.gz` 为对应项目及上游源码归档，旁边的 `.sha256` 文件用于传输后的完整性核对。构建和打包不执行系统安装；安装与卸载仅支持当前启动磁盘，在目标 Mac 上运行安装包并按提示重启。

默认构建使用本地 ad-hoc 签名，属于开发测试交付，尚未公证。正式交付时可通过 `MIXER_CODESIGN_IDENTITY`、`MIXER_INSTALLER_IDENTITY` 指定 Developer ID 签名身份，并可用已配置的 `MIXER_NOTARY_PROFILE` 进行公证。不要将证书或认证凭据写入源码。

用户操作见 [使用说明](docs/使用说明.html)。安装后添加输入、开始混音，在其他 App 中选择 `Mac Mic Mixer`；关闭窗口继续运行，退出应用停止处理。
